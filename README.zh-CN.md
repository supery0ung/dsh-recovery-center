# DSH 恢复中心

DSH 更新快，插件偶尔会让整个界面无法加载。恢复中心会在系统正常时保存插件和加载配置；发生崩溃后，可以离线恢复到之前的正常状态。即使 DSH 网页已经打不开，独立应急页面仍然可以启动。

它解决的是一个很具体的问题：一次不兼容的主题、前端插件或依赖更新，可能让 DSH 白屏、无法进入设置，甚至连出问题的插件都删不掉。恢复中心让恢复操作不再依赖已经崩溃的 DSH 页面。

**预览版 0.1.2**：已验证 macOS、Node.js 22、DSH 0.1.2-rc.1。Linux 已实现但未经实机验证；Windows 暂不支持。恢复前会中断 DSH 正在执行的任务。

## 安装

```sh
dsh plugin --profile web add dsh-recovery-center@0.1.2 --config.auto-install-peers=false
```

重启 DSH，进入「设置 → 恢复中心」。界面跟随 DSH 的中英文语言设置；独立应急界面可单独切换语言。

## 使用

1. 系统正常时，填写名称并保存第一个恢复点，例如“当前正常配置”。
2. 每次安装主题或更新插件前，再保存一次。
3. 发生崩溃后，选择最后一个正常恢复点，确认恢复并重启。
4. 如果 DSH 网页无法打开，双击桌面的 `DSH Emergency Recovery-安装标识.command`，从独立恢复页执行恢复。使用期间保持终端窗口开启。

首次启用时，本地 Mac 会自动生成桌面入口（需要桌面存在且可写）。「独立应急入口」显示实际位置，并可创建或修复入口。文件被删后，也可重启 DSH 重新生成。

入口使用各自电脑的安装路径，打开随机本机端口，不访问作者电脑。恢复程序存放在插件目录之外，恢复旧插件或移除插件后仍会保留。入口位于运行 DSH 的电脑；Linux 或通过 SSH 启动时保留独立启动文件，不自动创建 Mac 桌面入口。配置 `desktopShortcut: false` 可关闭自动创建桌面入口。

## 恢复范围

恢复当前 profile 的插件文件、依赖清单及加载配置，包括 `node_modules`、`package.json`、锁文件、Cordis 配置和 `.dsh-market/state.json`。不恢复聊天、工作区文件、DSH 主程序或单独存储的模型凭据。插件加载配置可能包含私人信息，请勿公开恢复点。

恢复前校验 SHA-256、profile 和 DSH 版本；自动保存恢复前状态。恢复包含实际插件文件，不依赖重新联网下载。事务日志用于中断后修复。外部依赖符号链接会被拒绝；内部链接原样保留。

恢复点不会自动清理，大小约为已安装依赖的大小；APFS 克隆可共享磁盘块。备份期间不要同时安装或更新插件。此插件不是整机或完整 DSH 备份工具。

## 受管理的服务

使用 launchd、systemd、pm2 或 Desktop 管理 DSH 时，关闭自动重启（`allowRestart: false`），先通过服务管理器停止 DSH，再使用离线恢复命令。自动检测仅尽力而为。

更多离线命令、目录位置及开发说明见 [English README](README.md)。
